# magpie 额度

在岛仔的状态详情页按平台汇总查看本机 magpie 各账号的剩余额度、近 15 天用量和额度圆环；「AI 额度」页签保留当前选中账号的前 3 个可换算窗口。

插件只读 magpie 的额度缓存。同一平台的多个账号合并成一行，余额直接显示金额，积分显示剩余数量，其余显示剩余百分比。

## 启用

安装插件后，在「设置 → 插件 → 已安装」启用，再选择「授权数据源」并填写本机的完整地址：

```text
http://127.0.0.1:3425/v1/magpie/quotas/cards
```

较旧的 magpie 没有 `/quotas/cards` 时，可改填带 `kept=1` 的旧端点。该参数让 magpie 只返回已有缓存，不会向上游查询：

```text
http://127.0.0.1:3425/v1/magpie/quotas?kept=1
```

不要填写不带 `kept=1` 的旧路径：那会让 magpie 主动查询上游额度，插件的 60 秒刷新会持续触发上游请求。

授权后打开「设置 → 页面管理 → 插件页面」，找到「magpie 额度」并点「打开」，即可在岛上看到状态页。

### 地址从哪里来

magpie 的本机网关固定监听 `127.0.0.1:3425`（见 magpie 官方 README），额度接口就在这个地址下，不需要另外查端口。想确认 magpie 是否正常，可在浏览器打开上面的完整地址，能看到 `data` 数组即可。

授权对话框由岛仔管理，插件不能预填或代为提交。为方便粘贴：

- 首次启用、尚未授权时，岛仔会弹一次「magpie 地址待授权」提醒，正文里带完整地址。
- 插件设置里有一项「授权地址」，默认就是完整地址，可长期作为复制来源；它只是复制参考，改这里不会改变授权。
- 状态页的未授权、错址页面会把完整地址显示为强调色，点一下即可复制，再粘贴到「授权数据源」。
- 插件只支持本机回环地址；如果用 Docker 或远程 magpie，请把地址指向本机能够访问的 loopback 端口。

岛仔的「授权数据源」对话框由宿主管理，插件不能预填或代为确认，所以复制后仍需要你在对话框里点一次「授权读取此地址」。

## 账号设置

「账号」设置可填「自动选择」，或厂商、显示名、登录名、别名中的任意一个：

- 填了具体账号时，「AI 额度」页签优先显示它的读数；找不到唯一匹配（包括多个账号同名）时按未知处理，页签不显示读数，也不拿别的账号冒充。
- 自动选择会记住上次选中的账号（沿用 1.x 的固定账号逻辑），账号消失或身份重复时按未知处理，不拿别的账号冒充。
- 名额读数没有可换算窗口时，页签不显示读数；状态详情页不受影响，仍然汇总全部平台。

## 页面说明

- **按平台合并**：同一个 `provider` 下的多个账号只显示一行，名称后面标出账号数（如 `WorkBuddy ×3`）。有 `Total` 一类汇总窗口时优先显示它，否则显示剩余比例最低的窗口。
- **余额**：直接显示 magpie 给出的金额，例如 `¥66.30`。`sharedBalance` 相同的账号只显示一次；没有声明共享的账号各算各的，多个钱包显示为 `¥5.00 等2个`。
- **积分**：显示剩余数量，例如 `7180 积分`。多账号按各自的 `limit` 加权累加；没有上限的套餐显示剩余百分比，例如 `剩 96.8%`。
- **窗口口径**：同名窗口只有单位相同时才合并；不同单位的同名窗口分别保留，不会把积分和 token 相加。
- **圆环**：最多显示 4 个剩余比例最低的平台，颜色按剩余比例变化（≥50% 绿、≥20% 橙、其余红）。
- **柱状图**：只聚合同一单位的用量（取记录最多的单位），不跨单位相加。日期轴为最近 15 个自然日、止于今天，每天一根柱子；缺日不画柱、也不挪动其它柱子的槽位，单天有值同样画一根柱。晚于今天的日期不画，也无法解析的日期（如 `2026-13-45`）会被跳过，不会挤掉真实数据。
- **缓存时间**：右上角一行小字，例如「缓存 18:54」，取自卡片的 `readAt`。有多张卡片时取最早的一个，超过 30 分钟显示「较早缓存」，不会把旧缓存当成刚更新；卡片没有 `readAt` 时不显示这一行。
- **一页展示**：不使用画布滚动，避免上下滑动被岛仔当成翻页。平台数量按档位自动排版：1 至 6 个单列，7 至 14 个两列，15 个以上三列；超过 21 个时先撤下圆环，超过 30 个时再撤下柱状图，把空间留给列表。一页最多列出 45 个平台，更多时底部提示未显示数量。
- **舍弃空账号**：条目报错且没有余额的账号（例如没有订阅的 ZCode）不会显示；只有无限额窗口的账号显示「无限」。
- **零余额**：合法的数字余额 `0` 是有效读数，正常显示为 `¥0`；只有字段缺失或类型非法才算未知。

## 错址提醒

只填写到 `http://127.0.0.1:3425/v1` 或填错路径时，插件会按响应形态发一次提醒：

- 返回接口索引（顶层有 `apis`）：提醒「授权地址不完整」，并给出完整地址。
- HTTP 200，但正文是 404 文本：提醒「授权地址不存在」。
- 返回的不是 JSON 或没有 `data` 数组：提醒「数据源不是 magpie 额度接口」。
- 有 `data` 数组，但里面没有可识别的 magpie 额度卡片：提醒「数据格式不符」，状态页显示「返回数据不是 magpie 额度格式，请核对地址」。

真正的 HTTP 404 由宿主判为离线，插件拿不到正文，因此不会弹出「地址不存在」提醒，只在状态页显示离线引导。`data` 数组正常但账号都没有额度时，状态页显示「账号均无额度」，与上面两种错误分开。

每个提醒 ID 只显示一次。magpie 未运行或端口不通时，宿主只能报告离线，无法区分「没启动」和「路径不对」，因此不发送提醒，只在状态页显示引导。

## 来源与范围

- 数据来自 [magpie](https://github.com/yetone/magpie)（MIT）的本机只读接口 `GET /v1/magpie/quotas/cards`；旧版 magpie 可用 `GET /v1/magpie/quotas?kept=1`，该参数同样只返回缓存。两个接口一次刷新只请求一次，不读取 magpie 保存的任何凭据，也不触发 magpie 向上游刷新。插件不接触 API Key、Cookie 或登录文件。
- 插件走 SDK 的本机回环数据源，由宿主直连 `127.0.0.1`，不经过系统代理，不带转发头；读取上限沿用宿主的 128 KiB / 2 秒。
- 剩余比例优先取 `windows[].remaining`（旧端点直接给出）；没有该字段时用 `used` 换算。`limit` 是窗口上限，`amount` 是已用数量，因此剩余量按 `limit × 剩余比例` 计算。`resetsAt`、`holdsWhy`、`runsOut` 等字段不展示。
- `unlimited` 窗口没有上限，`text` 窗口只有厂商文字，`balance` 是钱包余额（`used` 不是读数），这三类不换算成百分比；只有无限额窗口的账号显示「无限」。
- 条目级 `error`、`pluginError` 或 `readError` 非空时，该账号本次读数不可信。没有余额的报错账号直接舍弃；有余额的仍显示余额。
- 平台名称、账号数和数值都在画布内按宿主上限截断，不写重置日期和额外说明，避免界面拥挤。
- 「AI 额度」页签的窗口沿用 1.1.0 的映射：`label`、`remaining_pct`，以及可解析时的 `reset_at`（秒级时间戳）。

接口协议和数据结构属于 [yetone/magpie](https://github.com/yetone/magpie) 项目；岛仔由 [Renly1994](https://github.com/Renly1994) 维护。本插件为社区投稿，与上述两个项目没有隶属关系。

## 常见问题

**「AI 额度」里没有 magpie 额度读数？**

当前选中账号没有可换算的窗口（例如只有钱包余额或无限额窗口）时，页签不显示读数；状态详情页仍会汇总全部平台。账号设置填了具体账号时，优先显示该账号的读数；找不到该账号或同名账号不止一个时按未知处理，不显示读数，也不会换选别的账号。

**状态页没有内容？**

确认 magpie 正在运行，并在浏览器打开所填地址能看到 `data` 数组。地址只填到 `/v1`、magpie 未运行或未授权时，状态页会直接显示对应的引导和完整地址示例。

**平台很多，列表显示不全？**

列表会自动换成两列或三列并压缩行高；平台超过 21 个时圆环先让位，超过 30 个时柱状图也让位，优先保证平台列表。一页最多列出 45 个平台，再多会在底部提示未显示的数量。
